# Support

EcompJr maintains Dokploy Offload. For setup questions, bugs, and feature requests, [open a repository issue](https://github.com/ecompjr/dokploy-offload-action/issues). Check the [README](README.md) and [examples](examples/) first.

Include the action commit used, selected service mode, runner type, expected behavior, and a minimal reproduction or sanitized error output. Remove tokens, webhook URLs, personal data, and confidential application content. Use the [security reporting process](SECURITY.md) for vulnerabilities or confidential reports.

Support is provided by project maintainers as availability allows, with no guaranteed response or resolution time and no uptime SLA. Maintainers triage reports, request reproduction details when needed, and publish fixes through the release workflow. A support request is not permission to access your infrastructure. This policy does not replace obligations under the GitHub Marketplace Developer Agreement.

Maintenance focuses on the current `release` branch. When reporting an issue with a pinned commit, mention whether it also occurs on the current release. Historical commits do not have a separate backport commitment. Users control when to update their pinned workflows.

GitHub Actions, GHCR, Docker build tools, and Dokploy or VPS operation have separate support channels. The action builds images and requests deployment; an accepted webhook does not confirm application health.
